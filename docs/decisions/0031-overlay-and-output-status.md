# 0031 悬浮面板、输出状态与脚本收藏

- 状态：已采纳
- 日期：2026-10-21

## 背景

有人希望不打开编辑器，用一个始终可唤出的小面板操作项目里的开发命令：看长时间运行的 watch 是否还活着，一键跑常用脚本，危险命令先确认。watch 进程（webpack、typescript-to-lua）往往不占固定端口，现有的端口健康检查给不出「构建中 / 就绪 / 出错」。

## 决策

- 悬浮面板是第二个 BrowserWindow（透明、无边框、不出现在任务栏），由主进程的 `overlay-controller.ts` 创建。位置、用户拖出的宽度、以及上下拖动留下的高度上限存在 `userData/overlay.json`，显示时夹回当前显示器的工作区，默认在工作区右上角，默认宽 280。没拖过高度时窗口贴着内容；拖过之后那次高度是上限，内容更高就在面板里滚动，更矮就再缩回去。空区块不渲染，长期运行和收藏都空时只留一行说明。透明无边框窗口在 Windows 上没有可用的系统缩放边。窗口在 Windows 上保持不可由系统缩放，否则最外几像素是非客户区，点不到卡片内侧的把手，而系统缩放又被取消，左右边缘就完全拖不动。改大小只走把手（至少 8px，带缩放光标），按下时在捕获阶段停掉窗口拖动；主进程用 `setBounds`，Windows 上只在这次调用里临时允许系统改大小。置顶可关。窗口标题栏（设置按钮旁边）、托盘菜单、全局快捷键和 ShellApi 的 `toggleOverlay` 都能开关；快捷键放在核心设置 `overlayShortcut`（默认 `CommandOrControl+Alt+D`，即 Windows 的 Ctrl+Alt+D），设置页可改。整体不透明度是 `overlayOpacity`（0.3–1），只在设置页调整。面板上的按钮、隐藏、打开主窗口、内容高度和拖拽尺寸走 ShellApi，不进 `DevhubApi`。
- 面板复用同一份 renderer（`?view=overlay`）和现有的脚本 / 运行查询。双击一行（或「在主窗口打开」）让主窗口聚焦到该运行的终端标签。进程启动、停止仍只走 RunManager。
- `.devhub.yaml` 的脚本可以写 `status`：预设 `webpack`、`tstl`，或 `{ busy, ready, error }` 正则。`output-status-monitor` 只订阅事件总线，去掉 ANSI 后在最近输出里取**最后一次**匹配，因此 watch 可以在构建中、就绪、出错之间来回。结果用新事件 `run-output-status` 推送，主窗口脚本行和悬浮面板都显示。没有 `status` 的脚本仍走原来的端口健康检查。预设是按这些工具的常见输出写的，项目对不上就改正则。
- `confirm: true` 时，点击运行先弹出确认。批量任务直接调 core，不经过这个对话框。
- 收藏：`favorite: true` 写在项目文件里，作为默认；本机的星标存在 `favorites.json`，有记录就以记录为准（因此可以取消文件里声明的收藏，也可以给 npm 脚本加星）。主窗口可以只看收藏。悬浮面板的快捷按钮就是收藏。变更用 `favorites-updated` 推送。`setScriptFavorite` 的远程级别是 `control`（不新增可执行内容）。
- 长期运行列表另有一个开关，不跟收藏混用。`overlay: true` 是文件里的默认；本机选择在 `overlay-scripts.json`，有记录就以记录为准。主窗口脚本行上的面板图标改这一项。变更用 `overlay-scripts-updated` 推送。`setOverlayScript` 的远程级别同样是 `control`。声明了 `status` 但没有被选进列表的脚本，仍会在主窗口显示灯色，只是不占面板上的一行。
- 检测到的状态真正变化时发 `run-status-transition`（从哪到哪）。一开始写入的「构建中」不算变化，进程退出不算，同一种状态反复匹配也不发。提示动作改由 ADR 0032 的钩子执行。`.devhub.yaml` 的 `notify` 仍是该脚本就绪和出错的简写。`firstBuild: false` 跳过这次启动后的第一次就绪。`interval` 默认 15 秒。静音是 `notifyMuted`，总音量是 `hookVolume`。标题栏和悬浮面板各有一个喇叭，点开后调音量和静音，两边共用这两个值。面板太矮时会临时加高，让弹层留在窗口里。系统通知和播放 wav 在主进程，core 不引用 Electron。不新增依赖。
- 悬浮面板的空白、分区标题和间隙用指针拖动窗口：按下后超过几像素才开始，位移从拖动起点在主进程里计算。不用 `-webkit-app-region: drag` 包住整张卡片，因为 Windows 上父级 drag 区域会吞掉里面按钮和脚本行的点击，嵌套 `no-drag` 也不可靠。按钮、输入、开关、滑块、脚本行和终端输出都不启动拖动。文字默认不可选，只有展开后的终端 `<pre>` 可以选中复制。拖边缘时渲染进程暂停上报内容高度，主进程在手势结束前也不按内容改大小。把手在捕获阶段接住按下，避免和空白处的窗口拖动抢同一次指针。系统自己的缩放保持关掉，避免和把手的 `setBounds` 抢尺寸。多显示器时拖动按全部显示器 bounds 的并集移动，不夹在开始那一块屏幕上；松手只用窗口当前所在显示器的工作区贴边。只有一块屏幕时仍夹在它的工作区里。松手后若离该工作区边缘不超过 16 像素，窗口贴上那条边；贴上的边记在 `overlay.json`，之后高度变化仍贴着当前显示器的这一边。开始拖动会清掉旧的贴边。拖动和缩放过程中不贴边。

## 备选与理由

- 把面板做进 core：窗口、快捷键和屏幕坐标都是 Electron 的事，core 不能依赖 Electron。
- 把输出状态塞进 `RunHealth`：健康检查是端口 / HTTP，和「日志里最后一行算什么」不是同一件事，混在一起会让没有端口的 watch 一直停在「启动中」。
- 收藏只放 localStorage：两个窗口能共享，但手写的 `favorite` 和本机取消收藏不好一起测，手机端也读不到。
